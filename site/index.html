Your connection's speed on the taskbar,
and every second of it on record.

Internet Speed Meter is a native Windows app. It puts live download and upload beside the clock, in the clock's own size, records what crossed the network adapter once a second, kept forever, and runs a speed test whose every result sits beside the fastest second the meter itself saw. No browser, no server, no account.

How it works

One program, run as two processes. The part that runs all day is small and never loads the window's UI framework; the dashboard is started when its window opens and ends when it closes.

The meter SpeedMeter.exe --tray · all day · about 30 MB
  1. Sample the adapter once a secondThe busiest adapter, all of them summed, or one you pick. Filter layers and WAN miniports, which mirror an adapter's counters, are left out so no byte is counted twice.
  2. Draw the readoutTwo lines of text on the taskbar, the numbers in the tray icon, and the details panel, all in WinForms and GDI so nothing heavier is loaded.
  3. Write every second, and roll up every minuteEach second goes to a raw day file; each minute is folded into a month file with its fastest second each way, the bytes moved, and how many seconds were active.
  4. Never invent a peakA gap longer than 3 seconds, such as a resume from sleep, is recorded as a gap with no bytes, not filed against one second as a fake burst.
  5. Publish the live stateA 1 KB shared-memory block, rewritten every second, carries the rates, the adapter and a count of minutes written to whichever dashboard is open.
The dashboard SpeedMeter.exe --dashboard · only while open
  1. Read the history by local dayStamps are stored in UTC and bucketed by local time when read, so an early-morning hour is never filed under the day before.
  2. Find the best sustained averagesRolling 10-second, 1-minute and 5-minute windows over the raw seconds, which exist for as long as they are kept (14 days by default).
  3. Refresh when a minute landsIt polls the meter's block once a second; a new minute refreshes the page quietly, without replaying its entrance.
  4. Run speed tests in-processAgainst speed.cloudflare.com, then appended to speedtests.jsonl beside the history. Leaving the page does not stop a run.
  5. Go away completelyClosing the window ends the process, so its framework never sits in memory behind a closed window. A running test finishes and saves first.
The history on diskFixed-width, little-endian, append-only. Minute files are kept forever; raw files are pruned after rawretentiondays.

Flags: 1 connected, 2 gap, 4 adapter changed, 8 meter started. Two meters never record at once: a second copy, or the older meter this one replaces, is stopped or refused.

The meter

Taskbar readout

Windows taskbar

Two lines in the clock's font and size, coloured by the taskbar's theme rather than the app's, so they always read on it. The window is owned by the taskbar, follows it frame by frame when it auto-hides, stays above it when Start opens, and never takes focus from what you are typing. Click it for details, double-click for the dashboard, right-click for the menu.

Tray icon numbers

Notification area

Where the taskbar has no room (vertical, or crowded) the numbers move into the tray icon. At 16 px a vector font leaves about five pixels of ink, so the digits are a hand-placed pixel font, three pixels wide, which keeps "9.4M" and "118M" readable. One metric alone is stretched to twice the height. Larger icons use real type.

The dial

Test

The scale is logarithmic, and that is the whole design decision: a home connection can be anything from a few hundred Kbps to a gigabit, and on a linear dial sized for the fast case every ordinary speed sits pinned at the stop. Four decades of arc give 10 and 100 Mbps visibly different positions; the minor ticks at 2x and 5x keep it legible. Drag the slider; the needle eases in log space, as the app's does.

Everything it does

On the taskbar

  • Download and upload as two stacked lines, ↓ green and ↑ amber, in the clock's font and size.
  • At the left end of the taskbar or beside the clock.
  • Rides an auto-hiding taskbar frame by frame, paced by the compositor, and lets clicks through while the bar is hidden so the sliver that brings it back still works.
  • Stays above the taskbar when Start opens, and never takes keyboard focus.
  • Text colour matches the taskbar, or is forced light or dark.
  • Where the taskbar is vertical or has no room, the numbers move into the tray icon on their own.

Tray icon and menu

  • Numbers in the icon, in a hand-drawn pixel font at 16 px: both directions, download only or upload only, with or without unit letters, upload on top if you like.
  • Hovering shows both rates and the adapter, and says when recording has stopped.
  • Units in bytes (KB/s, MB/s) or bits (Kbps, Mbps), everywhere at once.
  • Adapter: Automatic (the busiest), All adapters (summed), or any one.
  • Start with Windows, Reset session counters, Run a speed test, Exit.
  • Right-click opens the menu on the first press, and a click anywhere else, the taskbar included, closes it.

Details panel

  • The adapter, the session's length, both live rates and a 60-second graph.
  • The session's totals each way and its fastest second.
  • Open dashboard and Run a speed test, one click each.
  • Painted by hand, so it stays crisp at any display scaling and needs nothing of the dashboard's framework.
  • Follows the taskbar's theme, like the readout.

A permanent record

  • Every second is sampled; every minute is rolled up and kept forever, at 40 bytes a minute.
  • One-second samples are kept for 14 days by default (rawretentiondays), or not at all.
  • Sleep, adapter switches and meter restarts are flagged in the record rather than guessed over.
  • A second counts as active above a combined rate you can set (activethresholdbps, 50 KB/s by default).
  • If recording fails it says so once: error.log, a notification, the panel's status line and the icon's tooltip. Nothing from before is lost.
  • The history folder can live on another drive, so it survives a Windows reset.

Speed page

  • Today's fastest second down and up, and the fastest ever, each with its minute.
  • Best sustained 10 s, 1 min and 5 min download averages.
  • On record: how many days the history covers, and since when.
  • The daily peak over 7, 30 or 90 days or everything; the choice is remembered.
  • These are observed speeds, what actually crossed the adapter, never a line rate. The page says so.

Speed test

  • Against speed.cloudflare.com: Standard 125 MB, Thorough 310 MB or Heavy 620 MB, the cost shown on each choice before you start.
  • Parallel (six streams, how fast the line is) or Single (what one download gets).
  • Latency idle and under load, on its own connection pool so probes never queue behind the transfers; bufferbloat shows as the rise.
  • Jitter as the median step between probes; packet loss from ICMP pings, ten a second, each counted against the phase it was sent in. No answer at all means "n/a", not 100%.
  • A note when latency rose 60 ms or more under load, and when a run was too short to trust.
  • Keeps running if you leave the page or close the window; Stop ends it.

Every run, kept

  • One line per run in speedtests.jsonl beside the history, so it moves and survives with it.
  • Size and connections, both rates, the three latencies, loss, how long it ran, data spent.
  • Meter saw: the fastest second the meter logged at the adapter during the run.
  • Runs from the earlier web dashboard read as they are, including ones taken on a phone.
  • 25 to a page, with a full pager and Go to page.

The dashboard

  • Dark (the default), light, or follow Windows. Light is designed on its own, measured to keep every shade visible on white.
  • Zoom with Ctrl+Plus, Ctrl+Minus, Ctrl+0 or Ctrl+mouse wheel; F5 re-reads the history.
  • Loading skeletons that are each page's own layout; cards rise in and numbers count up, skipped when Windows has animations off.
  • Refreshes itself each time a minute is written, without replaying anything.
  • Export history as CSV, and open the history, raw samples or settings folder.
  • A second launch of the app, from the Start menu or the exe, opens the dashboard instead of a second meter.
  • Set in Geist and Geist Mono, which ship with the app.

Light, and private

  • The meter that runs all day uses about 30 MB of memory and one sample a second.
  • The dashboard is a separate process, gone when its window closes.
  • Nothing leaves the machine except a speed test you start, which moves the amount it says it will.
  • No telemetry, no accounts, no update checks.

Install and uninstall

  • Per user, no administrator prompt: a Start menu entry, an Installed apps entry, start with Windows.
  • From a release zip, or built from source with the same script.
  • On a first install it asks where to keep the history and the one-second samples, suggesting a drive other than the system one.
  • After a Windows reset, give it the same folders: it reports how much history it found and carries on.
  • -NoStartup, -HistoryFolder, -RawFolder; -Uninstall never deletes the history.

Command line

  • speedmeter sample: the adapters, then a line a second of what the meter sees.
  • speedmeter stats: where the history is, and its records.
  • speedmeter export-csv: any range, minutes or raw seconds.
  • speedmeter speedtest: the same test, any size, parallel or single, saved or not.
  • speedmeter demo-data: an invented history, for screenshots like these.
  • --preview-icon and --preview-flyout draw the tray icon at every size and the panel on both taskbar themes.

A continuation, not a fresh start

  • The successor to an earlier C# tray meter and its web dashboard, and it reads exactly their files: the same settings.ini, history and speedtests.jsonl.
  • On first start it offers to stop the older meter, since two meters must never record at once.
  • The installer takes over the older meter's start-with-Windows entry.
